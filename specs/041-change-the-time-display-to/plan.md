# Implementation Plan: Digital Time Display and More Metronome Sounds

**Branch**: `041-change-the-time-display-to` (feature id 042) | **Date**: 2026-11-04 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/041-change-the-time-display-to/spec.md`

## Summary

Three independent changes on the Metronome page, plus one app-wide polish:

1. **Digital readout (US1, P1)**: the practice-timer readout and its `88:88` ghost use a new
   self-hosted face `'FM Timer Digits'`, a DSEG7 Classic Bold subset (`0`–`9`, `:`, SIL OFL 1.1)
   at `static/fonts/fm-timer-digits.woff2`, generated by `scripts/subset-timer-digits-font.mjs`
   from a dev-only source, declared in `global.css` with `font-display: swap`, preloaded only by
   `TimerCard.svelte`, precached by the existing service worker. Ships with ADR 0032 and a MINOR
   constitution amendment (2.2.0 → 2.3.0) of the "Fonts" row.
2. **Switches without state text (US2, P2)**: remove the `aria-hidden` On/Off `<span class="state">`
   from all five `role="switch"` controls and delete `metronome_switch_on/off`,
   `caged_switch_on/off` from the three catalogs. State stays visible (thumb, bold label) and in
   `aria-checked`.
3. **Five click sounds (US3, P3)**: `click` (unchanged), `wood`, `beep`, `rim`, `cowbell`,
   synthesized purely in `src/lib/audio/click.ts` with the same per-kind lengths and peaks;
   one global choice in a native `<select>` shown in every mode and phase; stored as
   `metronome.sound`; a mid-run change applies to clicks not yet scheduled via a new
   `ClickScheduler.setSound`; a stopped change plays one accent preview through the volume → mute
   chain.

Prerequisite done in this session: the branch was merged with `origin/main` (PR #65, feature
041) so `TimerCard`'s timer-link switch exists (research R-0).

## Technical Context

**Language/Version**: TypeScript 5 (`strict`), Svelte 5 runes, SvelteKit `adapter-static`

**Primary Dependencies**: Paraglide JS (messages), Valibot (prefs schema), Web Audio API; dev-only:
`subset-font` (existing), `dseg` npm package as the DSEG7 Classic source (new, devDependency, OFL
1.1; fallback: vendored TTF under `scripts/font-sources/`, research R-1)

**Storage**: `localStorage` preferences record v1 via `src/lib/prefs` (new additive field
`metronome.sound`)

**Testing**: Vitest (+ jsdom docblock for components), Playwright desktop project with axe

**Target Platform**: evergreen desktop browsers, 1024–2560 CSS px; offline via service worker (040)

**Project Type**: static single-page web app (SvelteKit, prerendered)

**Performance Goals**: CLS ≤ 0.1 on `/metronome` (preload + swap); initial JS ≤ 180 KB gzip
(expected growth < 2 KB); font file < 4 KB; no added latency to click scheduling (buffers cached
per sink per sound, rendered lazily)

**Constraints**: on-device synthesis only (no audio files); deterministic `renderClick`; click
length ≤ `CLICK_S` (0.03 s); sound change never moves a click time; font requested only by the
Metronome page; no network after load

**Scale/Scope**: 5 sounds × 3 kinds; 1 new component; 5 switch components edited; 6 new and 4
removed message keys × 3 languages; 1 font asset; 1 ADR; 1 constitution amendment

All open questions are resolved; decisions are in [research.md](research.md).

## Assumptions and rejected alternatives

- **Branch baseline**: merged `origin/main` (with the existing commit identity, since the
  worktree has no git user) rather than rebasing; the network fetch failed, but the local
  `origin/main` ref already contained PR #65.
- **Select visible while running**: the spec puts the select "in the metronome settings", but
  settings fields are hidden while running, and US3-6 / FR-010 require changing the sound
  mid-run. The select is therefore placed below the settings/run block so it shows in every
  phase. Rejected: settings-only placement (makes FR-010 unreachable).
- **Bold weight** of DSEG7 Classic chosen to match the readout's existing bold weight. Rejected:
  Regular (thinner strokes, lower legibility at a distance).
- **Prefs imports `CLICK_SOUNDS` from `$lib/audio/click`** instead of a mirrored constant with a
  parity test; the lint rule only forbids `$lib/audio/engine` in prefs.
- **No cancellation of pending clicks on a sound change**: up to `HORIZON_S` of old-sound clicks
  may still play, as the spec allows. Rejected: retime-style cancel and reschedule.
- **Synthesis parameters** (research R-7) are a starting point; a listening pass may tune
  frequencies and envelopes without changing the contracts (lengths, peaks, determinism).
