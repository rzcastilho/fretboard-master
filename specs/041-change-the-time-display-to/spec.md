# Feature Specification: Digital Time Display and More Metronome Sounds

**Feature Branch**: `feature/041-change-the-time-display-to`

**Created**: 2026-11-04

**Status**: Draft

**Input**: User description: "Implement the feature specified in specs/autonomous/ad-hoc/042-change-the-time-display-to.md (id 042, change-the-time-display-to)." (Change the time display to a digital font; remove the redundant state label next to the `Start and stop with metronome` toggle; provide more sounds for the metronome.)

## Clarifications

### Session 2026-11-04 (specify)

- Q: Which "time display" gets the digital look? → A (default): the practice-timer readout (`MM:SS`) on the Metronome page, the only clock-style time display in the app (spec 039). Other numbers (BPM, counts, status box) are unchanged.
- Q: How many new sounds, and which? → A (default): at least 4 additional selectable click sounds beyond the current one. All are synthesized on device (no audio files), and all keep the accent / normal / subdivision distinction.

### Session 2026-11-04 (clarify)

- Q: Does the `Start and stop with metronome` toggle exist? → A (derived from the repository): yes. Feature 041 (`b18d24c`, merged to `main` in PR #65) added it to `TimerCard.svelte` as a `role="switch"` button labelled `timer_link_label`, followed by an `aria-hidden` `<span class="state">` that shows `metronome_switch_on` / `metronome_switch_off`. This feature branch was cut before that merge, so **the branch MUST be brought up to date with `origin/main` before planning**; the earlier "toggle may not exist" assumption is withdrawn.
- Q: Remove the state text only from that toggle, or from every switch? → A (default, consistency of the switch control family, ADR 0028): the user's reason ("the toggle already shows the state") applies to every `.switch` in the app, and the same On/Off `<span>` pattern appears in the Count In switch (`CountInSettings.svelte`), the Subdivision ratio switch (`RatioSettings.svelte`), the CAGED connections switch (`CagedTool.svelte`) and the CAGED layer switches (`CagedLayerList.svelte`). The state text is removed from **all five**, leaving one consistent switch family. State stays perceivable without colour (thumb position, plus bold label when on, per `controls.css`) and is exposed through `aria-checked`. The now-unused messages `metronome_switch_on/off` and `caged_switch_on/off` are deleted from all three catalogs.
- Q: Font file versus the constitution's "Fonts" row? → A (derived from constitution + ADR 0006 precedent): the constitution's Technology table currently says digits use the system UI stack. A self-hosted digit font therefore needs a constitution amendment, made the same way ADR 0006 added the accidentals subset (amendment 1.2.0): this feature adds **ADR 0032 "Timer readout digit font"** and a **MINOR constitution amendment** to the "Fonts" row with a Sync Impact Report, in the same PR. The amended row allows a second self-hosted subset used only by the timer readout; everything else keeps the system UI stack.
- Q: Which typeface? → A (default, licence + offline): **DSEG7 Classic** (by keshikan, SIL OFL 1.1, the same licence as the existing accidentals subset), subset to the glyphs the readout uses (`0`–`9` and `:`), committed as `static/fonts/fm-timer-digits.woff2` with its OFL licence text alongside (for example `static/fonts/OFL-DSEG.txt`), generated by a script in `scripts/` from a dev-only source. DS-Digital (dafont) is not used: its licence does not permit free redistribution. The `@font-face` family (`'FM Timer Digits'`) is referenced only by the readout, so no other page's render (HTML, CSS, preload) requests it. The file is under `static/`, so the offline copy (040) precaches it: the service worker fetches it in the background on its first install from whichever page the visitor opens first, like every other static file. That background precache fetch is expected and is not a page load of the font.
- Q: How do ghost segments and digit widths behave? → A (default, keeps 039 behaviour): the existing unlit `88:88` ghost and the live digits both use the digital face so the segments line up exactly; DSEG digits are fixed-width, and `font-variant-numeric: tabular-nums` stays for the fallback face.
- Q: What appears while the font is loading or if it fails? → A (default, constitution X "never blank"): `font-display: swap`, falling back to the current system UI stack with tabular numerals (today's look). A warm load (font in HTTP or offline cache) shows the digital face on first paint.
- Q: Which sounds? → A (default, conventional metronome set): five sounds, with stable stored IDs and localized names:

  | ID | English name | Character |
  |---|---|---|
  | `click` (default) | Click | today's sine burst, unchanged byte-for-byte |
  | `wood` | Wood block | short, hollow, mid pitch |
  | `beep` | Beep | soft electronic tone |
  | `rim` | Rim | sharp stick/rim click with a noise transient |
  | `cowbell` | Cowbell | metallic, two detuned partials |

  Each sound has `accent`, `normal` and `sub` variants with the same peak ordering as today (accent loudest, sub softest) and a length of at most `CLICK_S` (0.03 s), so scheduling and halt timing are unchanged. Any noise is generated by a seeded PRNG, so `renderClick` stays pure and deterministic for unit tests.
- Q: Where is the sound chosen, and is it per mode? → A (default, follows 035/036 settings patterns): one global choice shared by all three modes (Metronome, Ratios Training, Speed Training), shown as a native `<select>` labelled "Click sound" in the metronome settings of every mode, using the same field styling as `SubdivisionSelect`. Choosing a value takes one interaction once the select is open (SC-004).
- Q: Preview? → A (default): when the metronome is not running, choosing a sound plays one accent click of it once (through the shared volume → mute chain, so mute silences it). While running, there is no separate preview: the next scheduled click uses the new sound.
- Q: When does a change take effect while running? → A (default, mirrors 038 `retime`): clicks not yet scheduled use the new sound; clicks already scheduled within the look-ahead horizon (≤ `HORIZON_S`, 1.5 s) may keep the old sound. The beat grid, tempo and run state are untouched — no restart, no dropped or doubled beat.
- Q: How is it stored? → A (default, follows 039/041 additive fields): `metronome.sound` in the existing preferences record, one of the five IDs; absent, unknown or wrong-typed → `click`, without affecting other metronome fields. Stored last, only when not `click`. `PREFS_VERSION` stays 1. It falls under the existing `metronome` privacy category. It is not part of share links. "Erase preferences" resets it to `click`.
- Q: What uses the sound? → A (default): every metronome click — count-in, accent, normal, subdivision, ratios and speed training. The practice-timer end chime (039) and fretboard note playback are unchanged.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Read the timer at a glance in a digital style (Priority: P1)

A player has the practice timer running while playing. The countdown is shown in a seven-segment digital style so it reads like a familiar stopwatch or gym clock, legible from a distance.

**Why this priority**: It is the most visible change and independent of the others.

**Independent Test**: Open the Metronome page; the timer readout renders in the digital typeface, stays the same width as digits change, and remains readable in every theme.

**Acceptance Scenarios**:

1. **Given** the Metronome page, **When** the timer shows `02:00`, **Then** the readout digits and the `88:88` ghost both use the `'FM Timer Digits'` face (DSEG7 Classic subset).
2. **Given** a running countdown, **When** digits change each second, **Then** the readout does not shift or resize.
3. **Given** the app is offline after one online visit, **When** the Metronome page loads, **Then** the digital face displays on first paint, with no request to another origin.
4. **Given** any theme, light or dark, or high contrast, **When** the readout is shown, **Then** its contrast meets WCAG 2.2 AA.
5. **Given** a screen reader, **When** the readout is reached, **Then** its accessible text is unchanged by the font (still reads as minutes and seconds).
6. **Given** the font file fails to load, **When** the readout is shown, **Then** it renders in the system UI stack with tabular numerals (the current look), never blank.

---

### User Story 2 - Toggles without a redundant label (Priority: P2)

A player flips the `Start and stop with metronome` toggle. The toggle already shows on/off, so no extra "On"/"Off" text appears to its right. The same holds for every other switch in the app (Count In, Subdivision ratio, CAGED connections, CAGED layers).

**Why this priority**: Small polish; removes clutter.

**Independent Test**: Flip each switch on and off; no state text appears beside it, and its state remains perceivable (thumb position, bold label when on) and announced through `aria-checked`.

**Acceptance Scenarios**:

1. **Given** the toggle is off, **When** it is viewed, **Then** only its name label is shown, with no state text on its right.
2. **Given** the toggle is switched on, **When** it is viewed, **Then** no state text appears and the toggle visibly shows on.
3. **Given** a screen reader, **When** the toggle is focused, **Then** its name and on/off state are still announced.
4. **Given** the Count In, Subdivision ratio, CAGED connections and CAGED layer switches, **When** each is viewed on or off, **Then** none shows On/Off (or translated) state text.

---

### User Story 3 - Choose among more metronome sounds (Priority: P3)

A player picks a different click sound (Click, Wood block, Beep, Rim or Cowbell) because the default is tiring or hard to hear over their instrument.

**Why this priority**: Adds new capability, but needs more work and the core metronome is usable without it.

**Independent Test**: In any mode, open the "Click sound" select, choose each sound, start the metronome and hear the changed click; reload and the choice remains.

**Acceptance Scenarios**:

1. **Given** the metronome settings in any of the three modes, **When** the "Click sound" select is opened, **Then** exactly the five sounds (Click, Wood block, Beep, Rim, Cowbell) are listed with localized names, Click selected by default.
2. **Given** a sound is selected, **When** the metronome runs, **Then** accent, normal and subdivision clicks use that sound and remain distinguishable from one another.
3. **Given** the metronome is stopped, **When** a sound is chosen, **Then** one accent click of it plays once at the app volume, and nothing plays when muted; **Given** the metronome is running, **Then** no extra preview click is played.
4. **Given** a sound was chosen, **When** the page is reloaded, **Then** the same sound is selected.
5. **Given** a stored `metronome.sound` that is absent, unknown or not a string, **When** the app loads, **Then** `click` is used and other metronome settings are unaffected.
6. **Given** the sound is changed while the metronome runs, **When** clicks not yet scheduled play (at most `HORIZON_S` = 1.5 s later), **Then** they use the new sound, and every click time stays on the original grid (no dropped, doubled or shifted beat).
7. **Given** the sound is changed in one mode, **When** the user switches to another mode, **Then** the same sound is selected there.

### Edge Cases

- Reduced motion: the digital readout has no added animation (such as segment flicker).
- Missing font: if the typeface fails to load, the readout falls back to the system UI stack with tabular numerals (the current look).
- Languages (en, es, pt): sound names are translated; the readout digits are unaffected.
- Speed training, count-in, and alternating ratios work with every sound.
- Shared-view links and existing stored preferences continue to load unchanged; a record without `metronome.sound` loads as `click`.
- Erase preferences resets the sound to `click`.
- Sound unavailable (no audio): the select still works and is remembered; the existing visual-beat notice is unchanged.
- Print theme: the readout prints legibly.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The practice-timer readout and its `88:88` ghost MUST be displayed in the `'FM Timer Digits'` face, a DSEG7 Classic subset (`0`–`9`, `:`); no other element uses that face.
- **FR-002**: The readout MUST keep a fixed width as digits change, in all states (idle, running, paused, finished).
- **FR-003**: The typeface MUST be self-hosted at `static/fonts/fm-timer-digits.woff2` with its SIL OFL 1.1 licence text committed beside it, declared with `font-display: swap`, precached by the offline copy, and requested by the render of no page other than the Metronome page (no preload, and no element using the face, elsewhere). The service worker's background precache fetch of the file (040), which happens on install from any page, is exempt. ADR 0032 and a MINOR constitution amendment of the "Fonts" row (with Sync Impact Report) MUST land in the same PR.
- **FR-004**: The readout MUST meet WCAG 2.2 AA contrast in every theme and keep its existing accessible text.
- **FR-005**: No `role="switch"` control in the app — the `Start and stop with metronome` switch, Count In, Subdivision ratio, CAGED connections and CAGED layer switches — MUST show on/off state text; state is conveyed by thumb position and bold label, and exposed via `aria-checked`. The unused `metronome_switch_on/off` and `caged_switch_on/off` messages MUST be removed from all catalogs.
- **FR-006**: Users MUST be able to choose one of five click sounds — `click` (default, today's sound unchanged), `wood`, `beep`, `rim`, `cowbell` — from a native select labelled "Click sound", shown in all three metronome modes and shared across them. Choosing a sound while stopped MUST play one accent click of it.
- **FR-007**: Every sound MUST give distinct accent, normal and subdivision clicks (peak accent > normal > sub), each no longer than `CLICK_S` (0.03 s), synthesized deterministically on device (seeded noise only) without audio files.
- **FR-008**: The selected sound MUST apply to every metronome click (count-in, accent, normal, subdivision, ratios, speed training) and go through the shared volume → mute chain. The timer end chime and note playback MUST be unchanged.
- **FR-009**: The selected sound MUST be stored as `metronome.sound` in the preferences record (stored last, only when not `click`; `PREFS_VERSION` unchanged; `metronome` privacy category); an absent or invalid value MUST parse to `click` without resetting other settings. It MUST NOT be added to share links.
- **FR-010**: Changing the sound while running MUST apply to clicks not yet scheduled, MUST NOT restart the run or move any click time, and MUST NOT alter tempo, meter or other settings.
- **FR-011**: All new visible text (sound names, sound control label) MUST be available in English, Spanish and Portuguese.
- **FR-012**: The sound control MUST be keyboard-operable and have an accessible name.
- **FR-013**: Existing metronome and timer behaviour (start, stop, pause, chime, shortcuts) MUST be unchanged.

### Key Entities

- **Click sound**: one of `click` | `wood` | `beep` | `rim` | `cowbell`, each with accent, normal and subdivision variants; `click` is the default.
- **Sound preference**: `metronome.sound` in the preferences record, global across modes.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: In a visual check of every theme, 100% of timer states show the digital style with no digit-width jitter.
- **SC-002**: The timer readout displays in the digital style with the network disabled.
- **SC-003**: No on/off text appears beside any switch in the app, while each switch's state is still announced by a screen reader.
- **SC-004**: Users can switch to any of the 5 sounds in no more than 2 interactions (open select, pick) and hear it within 1.5 s while running.
- **SC-005**: In a listening check, the accent, normal and subdivision clicks of each sound are told apart by a listener.
- **SC-006**: A chosen sound is still selected after a reload in 100% of attempts.

## Assumptions

- The "time display" means the practice-timer readout; other numbers keep their current style.
- The dafont example only sets the visual direction; DSEG7 Classic (OFL 1.1) is used because DS-Digital is not freely redistributable.
- The `Start and stop with metronome` toggle exists on `main` (feature 041); this branch must be updated from `origin/main` before planning. This feature does not change the linking behaviour.
- Synthesis parameters per sound are decided in planning; the "listening by ear" check (SC-005) is a manual step recorded under "Manual checks" in `tasks.md`.
- Desktop-only app (spec 030); no phone layout work.
